# Go, Pack & See — Telegram-бот

**Интерактивный путеводитель по регионам России в Telegram.**
Выбирайте регион, читайте о нём и проходите пошаговые маршруты с историей, фотографиями и ссылками на карту — прямо в чате, без установки отдельного приложения.

## Возможности

- **Каталог регионов.** Главное меню строится автоматически из таблиц `regions` и `tours` в базе данных — новый регион появляется в боте без правок кода.
- **Раздел «О регионе».** Краткая справка с иллюстрацией, оформленная в Markdown.
- **Пошаговые маршруты.** Каждый маршрут — набор «страниц»-остановок с быстрой навигацией: ⏪ в начало, ⬅️ назад, ➡️ вперёд, ⏩ в конец.
- **Кнопка «Показать на карте».** Для любой страницы маршрута можно указать ссылку на точку на карте; если ссылки нет, кнопка не показывается.
- **Богатое оформление.** Контент пишется в Markdown, хранится в базе данных и отправляется как rich-сообщения Telegram (заголовки, цитаты, изображения, выделение).
- **Навигация в одном сообщении.** Меню переключаются редактированием текущего сообщения, поэтому чат не засоряется.
- **Ссылка «К началу страницы»** автоматически добавляется к длинным текстам.
- **Картинки из хранилища.** Изображения хранятся в Supabase Storage и подключаются в Markdown как `![Подпись](local:имя.jpg)`. Бот сам загружает их в Telegram и запоминает `file_id`, поэтому повторный показ происходит мгновенно.
- **Случайная картинка.** Шаблон со звёздочкой (`local:main_menu_*.jpg`) при каждом показе выбирает одну из подходящих картинок — так главное меню каждый раз встречает новым видом.
- **Предложения регионов и баг-репорты.** Пользователи могут предложить новый регион/маршрут или сообщить об ошибке — всё сохраняется в базу данных Supabase.
- **Контент из базы данных.** Тексты и картинки загружаются из Supabase один раз при запуске; если загрузить их не удалось, бот не стартует.
- **Устойчивость к ошибкам.** Единый обработчик ошибок сообщает пользователю о проблеме и ведёт журнал, а безобидные ситуации (например, `message is not modified`) игнорирует.

## Как это выглядит для пользователя

```
/start
 └─ Главное меню ─ список регионов
     └─ Регион
         ├─ О регионе ─ справка
         └─ Маршруты
             └─ Маршрут (страницы 1…N)
                 ├─ Показать на карте
                 └─ ⏪  ⬅️  ➡️  ⏩
```

## Быстрый старт

### Требования

- Python **3.12+**
- [uv](https://docs.astral.sh/uv/) (рекомендуется) или `pip`
- Токен бота от [@BotFather](https://t.me/BotFather)

### Установка и запуск

```bash
# 1. Клонируйте репозиторий
git clone <URL-репозитория>
cd Go-Pack-See-Telegram-Bot

# 2. Установите зависимости
uv sync

# 3. Создайте файл с настройками и впишите токен и ключи Supabase
cp .env.example .env

# 4. Запустите бота (long polling)
PYTHONPATH=src uv run python main.py
```

> Модули импортируются как `handlers`, `keyboards`, `utilities`, поэтому каталог `src` должен быть в `PYTHONPATH` (в PyCharm достаточно пометить `src` как *Sources Root*).

Установка без `uv`:

```bash
python -m venv .venv && source .venv/bin/activate
pip install "aiogram>=3.31.0" "python-dotenv>=1.0.0" "supabase>=2.0"
PYTHONPATH=src python main.py
```

Остановить бота — `Ctrl + C`.

## Конфигурация

Настройки читаются из `.env` (через `python-dotenv`).

| Переменная  | Обязательна | Описание                          |
|-------------|:-----------:|-----------------------------------|
| `BOT_TOKEN` |     да      | Токен Telegram-бота от @BotFather |
| `SUPABASE_URL` | да       | Адрес проекта Supabase, например `https://xxxx.supabase.co` (без `/rest/v1/`) |
| `SUPABASE_KEY` | да       | Секретный ключ проекта (`secret` / `service_role`) из Project Settings → API Keys |

Если `BOT_TOKEN` не задан, бот завершится с сообщением `BOT_TOKEN not set`. Если не заданы переменные Supabase или база недоступна, бот завершится с сообщением `Бот не запущен: <причина>`.


## База данных

Весь контент бота и отзывы пользователей хранятся в [Supabase](https://supabase.com/) — облачном PostgreSQL с файловым хранилищем. Бесплатного тарифа достаточно, отдельный сервер не нужен.

```
                 ┌─ таблицы regions, tours ─┐
 Supabase ───────┼─ таблица markdown ───────┼─ при запуске ─► память бота
                 └─ хранилище images ───────┘
                 ┌─ таблица suggestions ◄── /suggest
                 └─ таблица bug_reports ◄── /bug_report
```

- **База — единственное место хранения контента.** Каталог регионов и маршрутов лежит в таблицах `regions` и `tours`, тексты меню, «О регионе» и страниц маршрутов — в таблице `markdown`, картинки — в хранилище `images`. В репозитории их нет.
- **Бот загружает контент один раз.** При запуске каталог, тексты и картинки читаются в память, дальше бот отвечает без сетевых запросов. Если загрузка не удалась, бот не стартует.
- **Отзывы пишутся сразу в базу.** `/suggest` и `/bug_report` добавляют строку в соответствующую таблицу.

### Таблицы

| Таблица        | Поля                                                                 | Назначение                                   |
|----------------|----------------------------------------------------------------------|----------------------------------------------|
| `regions`      | `id` (первичный ключ), `slug` (уникальный), `title`, `position`      | Регионы: кнопки главного меню в порядке `position` |
| `tours`        | `id` (первичный ключ), `region_id`, `slug`, `title`, `pages`, `map_links`, `position`; пара `(region_id, slug)` уникальна | Маршруты региона |
| `markdown`     | `kind`, `name`, `content`, `updated_at`; первичный ключ `(kind, name)` | Тексты меню, «О регионе» и страниц маршрутов |
| `suggestions`  | `id`, `created_at`, `user_id`, `username`, `region_name`, `tour`     | Предложения новых регионов и маршрутов       |
| `bug_reports`  | `id`, `created_at`, `user_id`, `username`, `report`                  | Сообщения об ошибках                         |

- `tours.region_id` ссылается на `regions.id` (внешний ключ): каждый маршрут привязан к своему региону, удаление региона удаляет и его маршруты.
- `tours.map_links` — JSON вида `{"2": "https://…"}`: номер страницы → ссылка на карту.
- `slug` региона и маршрута — только `a-z`, `0-9`, `_` (проверяется самой базой).
- `kind` — раздел контента: `menus`, `about_region` или `tours`.
- `name` — имя страницы, например `nizhnynovgorod_nizhnynovgorod_3` (правила имён — в разделе [Как добавить новый регион и маршрут](#как-добавить-новый-регион-и-маршрут)).
- `id` и `created_at` в таблицах отзывов проставляет сама база.

Картинки лежат в приватном хранилище (bucket) **`images`**; в Markdown на них ссылаются по имени файла: `local:имя.jpg`.

### Первоначальная настройка

Выполняется один раз на весь проект.

1. Создайте проект на [supabase.com](https://supabase.com/): включите **Data API** и **automatic RLS**, выключите **Automatically expose new tables**.
2. Откройте **SQL Editor → New query**, вставьте содержимое `scripts/supabase_setup.sql` и нажмите **Run** — будут созданы таблицы `regions`, `tours`, `markdown`, `suggestions`, `bug_reports`, права для `service_role` и хранилище `images`.
3. Впишите `SUPABASE_URL` и `SUPABASE_KEY` в `.env` (см. [Конфигурация](#конфигурация)).

### Редактирование контента

Контент правится прямо в панели Supabase:

| Что                    | Где в Supabase                                                                 |
|------------------------|--------------------------------------------------------------------------------|
| Регион или маршрут     | **Table Editor → regions / tours**                                             |
| Текст страницы         | **Table Editor → markdown**: отредактируйте поле `content` нужной строки       |
| Новая страница         | **Table Editor → markdown → Insert row**: заполните `kind`, `name`, `content`  |
| Картинка               | **Storage → images → Upload file**; для замены загрузите файл с тем же именем  |

После изменений **перезапустите бота** — контент загружается только при старте.

> База общая для всей команды: изменения сразу становятся актуальными для всех запусков бота.

### Модуль `database.py`

| Объект               | Назначение                                                                 |
|----------------------|----------------------------------------------------------------------------|
| `get_client()`       | Создаёт при первом вызове и возвращает общий асинхронный клиент Supabase   |
| `load_content()`     | Загружает таблицы `regions`, `tours`, `markdown` и хранилище `images` в память; при ошибке поднимает `ContentLoadError` |
| `region_rows`, `tour_rows` | Строки таблиц `regions` и `tours`, из них `load_data.get_regions` собирает каталог |
| `markdown_store`     | Словарь `(kind, name) → текст`, из него читает `load_data.read_markdown`   |
| `image_store`        | Словарь `имя файла → байты`, из него берёт картинки `LocalImagesMiddleware` |
| `insert_row()`       | Добавляет строку в таблицу; используется в `save_data.py`                  |

### Безопасность

- Бот и скрипт работают с **секретным ключом** (`service_role`), он хранится только в `.env`.
- На всех таблицах включён **Row Level Security** без разрешающих правил, поэтому с публичным ключом прочитать или изменить данные нельзя.
- Хранилище `images` приватное: файлы не доступны по прямой ссылке.

### Ограничения бесплатного тарифа

- 500 МБ под базу, 1 ГБ под файлы — с большим запасом для текущего контента.
- **Проект засыпает после 7 дней без запросов.** Тогда бот не запустится с ошибкой `Бот не запущен: …` — откройте панель Supabase и нажмите **Restore project**.

| Ситуация                                   | Поведение бота                                                    |
|--------------------------------------------|-------------------------------------------------------------------|
| Нет `SUPABASE_URL` / `SUPABASE_KEY`, неверный ключ, нет сети, проект на паузе | Не запускается: `Бот не запущен: <причина>` |
| Таблица `regions` или `markdown` пуста     | Не запускается: `Таблица … пуста`                                 |
| Нет нужной страницы или картинки           | Работает; на этой кнопке пользователь видит сообщение об ошибке    |
| Supabase недоступен во время работы        | Меню и маршруты работают (они в памяти), сохранение отзывов — нет |

## Архитектура

Бот построен на **aiogram 3** и разделён на независимые слои:

| Слой             | Каталог / файл                      | Ответственность                                                     |
|------------------|-------------------------------------|---------------------------------------------------------------------|
| Точка входа      | `main.py`                           | Загрузка `.env`, сборка `Dispatcher`, запуск polling                |
| Обработчики      | `src/handlers/`                     | `command_handlers` (команды и FSM), `navigation_handlers` (inline-навигация), `error_handlers` (глобальные ошибки) |
| Клавиатуры       | `src/keyboards/`                    | Построение inline-клавиатур из каталога регионов                    |
| Callback-данные  | `src/data/callbacks.py`             | Типизированный `Nav(action, region, tour, page)` на `CallbackData`  |
| Состояния FSM    | `src/data/forms.py`                 | Состояния диалогов предложений и баг-репортов                       |
| База данных      | `src/utilities/database.py`         | Подключение к Supabase, загрузка контента при старте, запись строк  |
| Загрузка данных  | `src/utilities/load_data.py`        | Каталог регионов из таблиц `regions`/`tours` (кэшируется `lru_cache`), выдача Markdown из загруженного контента |
| Сохранение данных| `src/utilities/save_data.py`        | Запись предложений и баг-репортов в таблицы Supabase                |
| Middleware       | `src/middlewares.py`                | `AnswerCallbackMiddleware` — автоматический `callback.answer()`, чтобы кнопка не «зависала»; `LocalImagesMiddleware` — подстановка локальных картинок в исходящие rich-сообщения |
| Контент          | Supabase: таблицы `regions`, `tours`, `markdown`, хранилище `images` | Каталог, тексты и картинки — отдельно от кода |
| Скрипты          | `scripts/supabase_setup.sql`        | Создание таблиц и хранилища в Supabase                              |

**Ключевые решения**

- **Контент отделён от кода.** Каталог, тексты и картинки хранятся в базе данных. Редактору не нужно трогать Python.
- **Валидация идентификаторов.** Slug региона и маршрута проверяются регулярным выражением `[a-z0-9_]+` — и в базе (`check`), и в коде при сборке каталога.
- **Неизменяемые модели.** `Region` и `Tour` — `frozen` dataclass со `slots`.
- **Единый путь ошибок.** Неизвестный регион, маршрут или отсутствующий файл поднимают `UnknownResourceError`, который перехватывается глобальным обработчиком.
- **Ручной ответ на callback там, где он нужен.** Для листания маршрутов флаг `manual_answer` отключает автоответ middleware, чтобы показать alert на границах маршрута («Вы находитесь на первой / последней странице»).
- **Контент загружается один раз.** Тексты и картинки читаются из Supabase при запуске и хранятся в памяти: нажатия кнопок не требуют сетевых запросов, а без контента бот просто не стартует. Подробнее — в разделе [База данных](#база-данных).
- **Локальные картинки через request-middleware.** `LocalImagesMiddleware` подключается к сессии бота (`bot.session.middleware(...)`) и перехватывает исходящие `SendRichMessage` и `EditMessageText`. Ссылки `local:…` заменяются на `tg://photo?id=…`, а сами файлы (из памяти, куда их загрузил `load_content()`) передаются в поле `media` у `InputRichMessage`. После первой отправки `file_id` берётся из ответа Telegram и кэшируется в памяти, дальше файл не загружается повторно (после перезапуска бота кэш строится заново). Хендлеры при этом не меняются, а картинки не зависят от внешних сайтов: нет протухших ссылок, ограничений хостинга и проблем с лицензиями чужих изображений.
- **Картинки по имени.** Middleware ищет картинку только по имени среди загруженных из хранилища `images`; ссылка на несуществующий файл вызывает `FileNotFoundError`.

## Как добавить новый регион и маршрут

Код менять не нужно — достаточно данных.

**1. Добавьте регион и маршрут в Supabase** (Table Editor):

`regions` — одна строка на регион (`id` база проставит сама):

| `slug`      | `title`   | `position` |
|-------------|-----------|------------|
| `tatarstan` | Татарстан | 1          |

`tours` — одна строка на маршрут; в `region_id` укажите `id` региона из таблицы `regions`:

| `region_id` | `slug`  | `title` | `pages` | `map_links`                                        | `position` |
|-------------|---------|---------|---------|----------------------------------------------------|------------|
| `2`         | `kazan` | Казань  | 10      | `{"1": "https://…", "3": "https://…"}`             | 0          |

| Поле        | Описание                                                                                     |
|-------------|----------------------------------------------------------------------------------------------|
| `id`        | Числовой идентификатор строки, проставляется базой автоматически                             |
| `region_id` | `id` региона, к которому относится маршрут                                                   |
| `slug`      | Идентификатор для бота и имён страниц: только `a-z`, `0-9`, `_`                              |
| `title`     | Название, отображаемое на кнопке                                                             |
| `position`  | Порядок кнопок (по возрастанию)                                                              |
| `pages`     | Количество страниц маршрута                                                                  |
| `map_links` | Необязательно: номер страницы → ссылка на карту. Для остальных страниц кнопка скрыта         |

**2. Добавьте страницы в таблицу `markdown` в Supabase** (Table Editor → markdown → Insert row) по соглашению об именах:

| Что                 | `kind`         | `name`                       |
|---------------------|----------------|------------------------------|
| Меню региона        | `menus`        | `{region}_menu`              |
| О регионе           | `about_region` | `about_{region}`             |
| Страница маршрута   | `tours`        | `{region}_{tour}_{page}`     |

Например, 3-я страница маршрута «Казань» в Татарстане — строка с `kind = tours`, `name = tatarstan_kazan_3`.

**3. Загрузите картинки** в Supabase Storage → `images`.

**4. Перезапустите бота.** Каталог и контент загружаются при старте.

**Рекомендации**

- Держите slug короткими: они упаковываются в `callback_data`, а у Telegram есть ограничение на её размер (64 байта).
- Картинки загружайте в хранилище `images` и подключайте как `![Alt](local:имя.jpg)`. Имена — по шаблону `{region}_menu.jpg`, `about_{region}.jpg`, `{region}_tour_{page}.jpg`.
- Несколько вариантов одной картинки называйте с общим началом (`main_menu_1.jpg`, `main_menu_2.jpg`, …) и подключайте шаблоном `local:main_menu_*.jpg` — бот будет выбирать случайную.
- Размер: горизонтальная картинка шириной 1280–1920 px (для карт и схем, которые будут приближать, — до 2560 px), желательно до 1 МБ. Telegram всё равно пережимает фото, поэтому больший размер только замедляет первую загрузку.
- Текст длиннее 700 символов автоматически получает ссылку «К началу страницы».

## Обратная связь от пользователей

Предложения и баг-репорты сохраняются в таблицы Supabase `suggestions` и `bug_reports` (время — в UTC). Посмотреть их можно в панели Supabase: **Table Editor → suggestions / bug_reports**.

Пример строки `suggestions`:

| id | created_at                | user_id   | username | region_name   | tour |
|----|---------------------------|-----------|----------|---------------|------|
| 1  | 2026-10-13 08:27:22+00    | 123456789 | example  | Пермский край | null |

Пример строки `bug_reports`:

| id | created_at                | user_id   | username | report            |
|----|---------------------------|-----------|----------|-------------------|
| 1  | 2026-10-13 07:58:59+00    | 123456789 | example  | Описание проблемы |

> Таблицы содержат персональные данные пользователей (ID и username) — не выгружайте их в репозиторий и не публикуйте.

## Разработка

Инструменты разработки устанавливаются группой `dev`:

```bash
uv sync --group dev

uv run ruff check .          # линтер (E, F, I, UP, B, ASYNC; длина строки 100)
uv run ruff format .         # форматирование
uv run mypy .                # проверка типов
```

**Стек:** Python 3.12 · [aiogram](https://docs.aiogram.dev/) 3.31+ · [Supabase](https://supabase.com/) (PostgreSQL + Storage) · python-dotenv · ruff · mypy.

**Рабочий процесс.** Изменения вносятся в отдельных ветках через pull request.
